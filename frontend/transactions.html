Transactions

ACID properties, SAVEPOINT, ROLLBACK, and COMMIT demonstrated live.

info

Each transaction runs in a real MySQL transaction block. Before/After states are fetched from the database to prove changes (or lack thereof after rollback).

TXN 1 Resource Update with SAVEPOINT + ROLLBACK

Demonstrates partial rollback: the update is undone by rolling back to a savepoint. Original status is preserved.

START TRANSACTION;
SAVEPOINT before_update;
UPDATE Cloud_Resource SET status='Stopped' WHERE resource_id=1;
-- Verify change...
ROLLBACK TO SAVEPOINT before_update;  -- Undo the update
COMMIT;

TXN 2 Insert Usage Log + COMMIT

Basic committed transaction. Log count increases by 1 after COMMIT.

START TRANSACTION;
INSERT INTO Usage_Log (resource_id, cpu_usage, memory_usage, storage_used)
    VALUES (2, 55.0, 60.0, 200.0);
COMMIT;  -- Permanently saves the new log

TXN 3 Billing Insert with Trigger Verification + COMMIT

Shows the calc_total_cost trigger computing total_cost inside a transaction before COMMIT.

START TRANSACTION;
SAVEPOINT pre_insert;
INSERT INTO Billing (resource_id, usage_hours, cost_per_hour, billing_date)
    VALUES (3, 100, 0.05, CURDATE());
-- calc_total_cost trigger fires: total_cost = 100 * 0.05 = ₹5.00
COMMIT;

TXN 4 DELETE with Full ROLLBACK

Demonstrates atomicity: a DELETE is completely undone by a full ROLLBACK. Resource 8 still exists after.

START TRANSACTION;
DELETE FROM Cloud_Resource WHERE resource_id=8;
-- Resource appears deleted inside transaction...
ROLLBACK;  -- Full rollback: resource is restored

TXN 5 Manual Suggestion Insert + COMMIT

Shows a manual (non-trigger) suggestion created in a transaction. Suggestion count increases after COMMIT.

START TRANSACTION;
INSERT INTO Optimization_Suggestion
    (resource_id, suggestion_type, reason, estimated_savings)
    VALUES (4, 'Migrate',
    'Migrate to ap-south-1 for 30% cost reduction.', 20.00);
COMMIT;
